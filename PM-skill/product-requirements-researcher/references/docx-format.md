# 调研报告 .docx 输出格式

> 从 SKILL.md 引用。当用户要求「导出 Word」「生成 docx」「要 Word 版」时使用。

## 格式规范

- **标题**：居中，加粗，主标题「项目需求调研报告」
- **项目基本信息表格**：两列（字段 | 内容），行顺序：项目名称、项目编号、调研开始时间、调研结束时间、调研小组、调研地点、调研目的、调研人员、被调研方/参与人员、本次调研轮次、关联历史报告
- **调研内容**：一个大表格包含全部调研内容
  - 第 1 行：表头「调研内容」（跨列合并）
  - 第 2 行：列标题「序号」|「问题与回答」
  - 第 3 行起：每行一条问题及回答要点
- **调研成果**：一个大表格包含全部调研成果
  - 第 1 行：表头「调研成果」
  - 第 2 行：小标题「现状」
  - 第 3 行起：现状编号列表及痛点、共识、风险依赖等

## 实现方式

```bash
node product-requirements-researcher/scripts/md-to-docx.js projects/<project-slug>/调研/YYYY-MM-DD-session-01.md
```

生成的 docx 与 md 同目录保存，文件名对应（如 `2026-02-27-session-01.docx`）。或调用 `docx` 技能时遵循上述格式。

## PRD 风格需求调研报告（可选）

当用户希望更「PRD 化」输出时，可参考 `templates/requirement-report.md` 的章节结构：

- 1. 项目背景
- 2. 用户角色
- 3. 核心业务流程
- 4. 功能需求
- 5. 数据需求
- 6. 非功能需求
- 7. 待定问题

不要用 PRD 结构替代最终调研报告，仅作附带引用。
