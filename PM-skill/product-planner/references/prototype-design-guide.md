# 原型设计指南

> 本文件供 product-planner skill 在设计页面原型时按需参考。

---

## 1. 原型设计的两个阶段

### 阶段一：MD 页面结构描述（默认必做）

**目的**：将功能清单转化为页面维度的结构描述，明确每个页面要干什么、展示什么、如何流转。

**何时使用**：每次出原型都先做这一步，是 HTML 原型的输入，也是 PRD 第 3 章「页面设计」的素材。

**核心价值**：
- 强迫思考页面的完整状态（空状态/加载/错误/正常）
- 理清页面间的流转关系，发现设计漏洞
- 轻量，修改成本低，适合快速迭代

### 阶段二：HTML 交互原型（按需生成）

**目的**：给业务方、客户演示，让他们直观感受产品形态；开发团队用于理解交互逻辑。

**何时使用**：
- 需要向客户/业务方展示产品 demo 时
- 页面交互较复杂，文字描述不直观时
- 用户明确要求「做个可以点的原型」时

## 2. MD 原型描述规范

### 2.1 必须包含的要素

每个页面描述必须包含以下要素（缺一不可）：

```markdown
### Pxx - 页面名称

**所属模块**：[一级模块名]
**页面地址**：`/路径`（仅 Web 端需要）
**页面用途**：[一句话说明这个页面帮用户做什么]

#### 主要页面元素

[表格形式列出页面上的所有主要元素]

#### 关键交互

[表格形式列出用户可以进行的操作及系统响应]

#### 数据展示

[展示字段列表，标注来源]

#### 状态变化

- 空状态：[无数据时的展示]
- 加载状态：[数据加载中的样式]
- 错误状态：[接口失败时的提示]

#### 页面流转

- 进入来源：[从哪些页面可以到达此页]
- 离开去向：[此页可以跳转到哪些页面]
```

### 2.2 页面命名规范

- 页面编号：`P01`, `P02`, `P03`... 按自然顺序编号
- 页面名称：功能导向命名，不要写技术名称
  - 好：`居民信息列表`、`事件上报表单`、`数据统计看板`
  - 差：`ListPage`、`FormView`、`Dashboard`

### 2.3 页面分类参考

| 类型 | 典型名称 | 核心元素 |
| --- | --- | --- |
| 列表页 | XX管理、XX列表 | 搜索栏、筛选条件、数据表格、分页、操作按钮 |
| 详情页 | XX详情、XX查看 | 基本信息区、关联数据区、操作按钮 |
| 表单页 | 新建XX、编辑XX | 表单字段、必填标注、提交/取消按钮 |
| 仪表盘 | 工作台、数据总览 | 统计卡片、图表、待办列表 |
| 设置页 | 系统设置、个人设置 | 分组配置项、保存按钮 |
| 流程页 | XX审批、XX处理 | 步骤条、当前步骤内容、操作按钮 |

## 3. HTML 原型设计规范

### 3.1 视觉风格

使用 Tailwind CSS CDN，遵循以下视觉规范：

| 元素 | 规范 |
| --- | --- |
| 主色调 | 蓝色系（`blue-600` / `#2563EB`） |
| 背景色 | 浅灰（`gray-50` / `#F9FAFB`） |
| 卡片背景 | 白色，细边框（`border-gray-200`） |
| 字体 | `Microsoft YaHei`（微软雅黑），确保 Windows 兼容 |
| 圆角 | 卡片 `rounded-xl`，按钮 `rounded-lg`，标签 `rounded` |

### 3.2 布局结构

标准后台管理系统布局：

```
┌──────────────────────────────────────────────────────┐
│  顶部导航栏（固定，高度 56px）                         │
│  [产品名称] [版本号] [原型标记]    [用户头像]          │
├─────────────┬────────────────────────────────────────┤
│             │                                        │
│  左侧菜单   │  内容区                                │
│  (宽 224px) │  (flex-1，内边距 24px)                 │
│             │                                        │
└─────────────┴────────────────────────────────────────┘
```

### 3.3 常用组件的 HTML 写法

**统计卡片**：
```html
<div class="bg-white rounded-xl border border-gray-200 p-5 shadow-sm">
  <div class="text-sm text-gray-500">指标名称</div>
  <div class="text-3xl font-bold text-gray-900 mt-1">1,234</div>
  <div class="text-xs text-green-600 mt-1">↑ 12% 较上周</div>
</div>
```

**操作按钮组**：
```html
<div class="flex gap-2">
  <button class="px-4 py-2 bg-blue-600 text-white rounded-lg text-sm hover:bg-blue-700">主操作</button>
  <button class="px-4 py-2 border border-gray-300 text-gray-700 rounded-lg text-sm hover:bg-gray-50">次操作</button>
  <button class="px-3 py-2 text-red-600 border border-red-200 rounded-lg text-sm hover:bg-red-50">危险操作</button>
</div>
```

**状态标签**：
```html
<span class="px-2 py-0.5 bg-green-100 text-green-700 rounded text-xs">已完成</span>
<span class="px-2 py-0.5 bg-yellow-100 text-yellow-700 rounded text-xs">处理中</span>
<span class="px-2 py-0.5 bg-gray-100 text-gray-500 rounded text-xs">已关闭</span>
```

**表单输入**：
```html
<div class="mb-4">
  <label class="block text-sm font-medium text-gray-700 mb-1">
    字段名 <span class="text-red-500">*</span>
  </label>
  <input type="text" class="w-full border border-gray-300 rounded-lg px-3 py-2 text-sm focus:outline-none focus:ring-2 focus:ring-blue-500" placeholder="请输入...">
</div>
```

### 3.4 原型中的"假数据"原则

- 使用真实感强的中文假数据（姓名、地址、日期等）
- 避免「示例文字」「测试数据」这类无意义占位
- 好的假数据让业务方更容易理解产品
- 推荐：网格员姓名用真实中文姓名，ID 用规范格式，时间用近期日期

## 4. 页面流转设计原则

### 4.1 流转图绘制规范

```
[列表页] --「点击新建」--> [新建表单页] --「提交成功」--> [列表页（刷新）]
                                         --「取消」--> [列表页]
[列表页] --「点击行」--> [详情页] --「点击编辑」--> [编辑表单页]
```

### 4.2 常见页面流转模式

| 模式 | 说明 |
| --- | --- |
| 列表 → 详情 | 点击行/查看按钮进入详情 |
| 列表 → 新建 | 点击「新建」按钮打开表单（新页或弹窗） |
| 详情 → 编辑 | 在详情页点击「编辑」进入编辑表单 |
| 表单 → 返回 | 提交成功/取消后返回来源页 |
| 工作台 → 各模块 | 工作台作为入口，点击统计卡片/快捷入口进入对应列表 |

### 4.3 弹窗 vs 新页面的选择

| 场景 | 推荐方式 | 原因 |
| --- | --- | --- |
| 简单表单（≤5 个字段） | 弹窗 | 减少页面跳转，操作更流畅 |
| 复杂表单（≥6 个字段） | 新页面 | 弹窗空间不足，体验差 |
| 删除确认 | 弹窗 | 轻量确认，不需要独立页面 |
| 详情查看 | 新页面（有大量信息时）或侧边抽屉 | 便于分享链接，信息展示更充分 |
| 图片/文件预览 | 弹窗/全屏遮罩 | 沉浸式体验 |

## 5. 原型评审清单

在提交原型前，逐项检查：

### 完整性
- [ ] 所有功能清单中的功能点都有对应页面
- [ ] 每个页面都有空状态设计
- [ ] 所有页面流转都可以到达（没有「死页面」）
- [ ] 表单页面有取消/返回路径

### 一致性
- [ ] 同类操作的按钮位置一致（如「新建」按钮统一在右上角）
- [ ] 状态标签的颜色含义一致（绿色=正常/成功，红色=警告/错误）
- [ ] 导航菜单在所有页面中显示一致

### 可用性
- [ ] 关键操作（如删除）有二次确认
- [ ] 表单必填字段有明确标注
- [ ] 列表页有搜索功能（数据量 > 20 条的列表）
- [ ] 数据加载有 Loading 状态描述
