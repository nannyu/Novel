# 功能可视化页面要求

## 页面目标

把功能清单转换成可浏览、可筛选、能辅助开发沟通的页面，帮助用户快速理解：
- 有哪些模块和功能点。
- 哪些是调研需求，哪些是系统补充。
- 哪些属于 MVP，哪些后续迭代。
- 每个功能点的开发说明和验收要点是什么。

## 推荐页面结构

### 顶部区域

- 项目名称
- 功能总数、P0/P1/P2 数量
- 调研需求数量、系统补充数量
- 最近更新时间

### 筛选与搜索

- 搜索框：按功能模块、功能点、描述搜索
- 模块筛选
- 优先级筛选
- 功能来源筛选
- MVP/阶段筛选（如已有阶段规划）

### 主内容

推荐使用以下任一布局：
- 模块分组卡片：适合中小型项目。
- 看板视图：按阶段或优先级分列。
- 表格 + 详情抽屉：适合功能点较多的后台系统。

每个功能点至少展示：
- 功能模块
- 功能点
- 功能来源
- 优先级
- 功能描述
- 开发说明
- 验收要点
- 备注或待确认项

## 交互要求

- 点击功能点可展开详情。
- 筛选和搜索即时生效。
- 保留空状态。
- 移动端可浏览，卡片或表格不应横向溢出。

## 视觉要求

- 默认使用清晰、现代、可扫描的业务系统风格。
- 若用户未指定风格，应结合 `frontend-design` skill 给出推荐并确认。
- 不要做营销落地页风格；这个页面是开发沟通和范围管理工具。
