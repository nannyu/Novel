# LLM Wiki 参考

本文件位于技能目录下的 `references/` 文件夹，与根目录 `SKILL.md` 配套；模板与触发词以本文件为补充真源。

## 触发词表

下列短语应触发主技能 `llm-wiki-kb`（与 `SKILL.md` 摘录互补；维护时两处保持语义一致）。

**英文**：create knowledge base、initialize knowledge base、build knowledge base、import source materials、compile wiki、maintain wiki、knowledge-base question、ask the knowledge base、archive to wiki、write back to wiki、update wiki index、update maintenance log、wiki health check、Obsidian wiki。

**中文**：创建知识库、初始化知识库、建库、导入资料、导入源材料、原始资料抽取、预处理资料、整理会议、整理截图、整理语音、整理图片、整理视频、外部资料收藏、多模态资料入库、人物档案、人物画像、项目档案、项目画像、对象型页面、我的判断、关系状态、当前结论、已废弃观点、自我模型、我的表达风格、使用反馈回写、时间线、编译 wiki、维护 wiki、问知识库、基于知识库回答、按我的方法论输出、归档到 wiki、回写 wiki、更新索引、更新维护日志、健康检查、把某知识点归集到 wiki、按我指定的范围编译 wiki、先总结源材料、只要总结输出到 output、总结后再入库、书本镜像、方法论镜像、把书和我的经历对应、把书里的流程编译成我的方法论、wiki 查重、是否已有相同总结、显式 `/llm-wiki-kb` 调用；**主题命名**、**合并进已有知识点页**、**不要从某某提炼这种文件名**、**材料来源写在实体里**。

## 查重判定与分支

| 标签 | 源覆盖与结论 | 默认动作 |
|------|----------------|----------|
| A 完全同质 | 用户给定源集合已被某页声明覆盖，且 `摘要`/「概述与综合」稳定论断与拟输出语义等价 | 对话提示并给出 wiki 路径；建议写 `output/wiki-dedupe/...`；不新建同质页、不写同质 summary（除非用户要对比稿） |
| B 部分重叠 | 源有交集但边界或结论不同 | 在既有页增量合并；编译报告注明「合并而非新建」 |
| C 无相关覆盖 | 未发现页面覆盖本次源范围 | 按需写 `output/summary/...`，再按指令编译 wiki 并写 `output/wiki-compile/...` |

启发式提醒：先索引缩小候选，再按**源路径字符串**检索 `实体`/「对应源材料」/正文链接；**结论同质**看稳定论断而非关键词撞车。

## 知识点编译维度（与主 SKILL 一致）

- 用户可**自定义**编译维度（如何切分主题、映射到哪些 wiki 页）；指定后优先执行。
- 用户**仅**要求「把笔记/材料编译进 wiki」而**未**说明维度时：**默认按源 Markdown 的标题层级**（`#`…）划分主题边界；**无标题**时由代理自拟提纲归纳并编译，并在 `实体` 或 `output/wiki-compile/...` 中简要说明归纳依据。

## 知识点文件命名（与主 SKILL 一致）

- **`知识点-*.md` = 主题页**，多份源材料在 **`实体`·材料来源** 用链接列出；**避免** `知识点-从某某提炼的某某.md` 等来源导向文件名（除非用户字面要求）。
- **简洁可识别（默认）**：中文主题片段倾向 **4～12 字** 名词性短语；去掉「关于/浅谈/笔记/总结/一文读懂」等赘词（除非即讨论对象）；需消歧时加最短限定词，勿把整段源文件名塞进主题名。用户显式给出的文件名以用户为准，可另给更短备选。
- **编译报告**：凡**新建页**且主题由源标题**压缩**而来，须在 `output/wiki-compile/...` 列「**原标题（或源小节标题） → 采用页名/文件名**」；无压缩可注明无映射。
- 查重发现已有同主题页时：**合并修订**优于再建同质新文件；编译报告注明「合并而非新建」。
- 仓库 `AGENTS.md` / `CLAUDE.md` 若有命名专条，**以仓库为准**。

## 最简AGENTS.md 模板

```markdown
# AGENTS — <知识库名称>

## 目录表

| 路径 | 用途 |
|------|------|
| `<sources_dir>/` | 源材料。只读。 |
| `wiki/` | 由代理维护的已编译wiki。 |
| `output/` | 派生输出，如Q&A和报告。 |

## 工作规则

1. 回答问题时先读取 `wiki/INDEX.md`。
2. 仅在wiki不足时才读取源材料。
3. wiki是总结式的编译层，而不是全文镜像。
4. 任何wiki页面变更时都要更新索引和维护日志。
5. 对用户指定的源材料做「先总结再 output/入库」时：**写入总结或改写 wiki 之前**必须在现有 `wiki/` 中查重；若已有同质总结，提示用户并给出页面路径，默认不重复建页；无同质时再写入 `output/summary/...` 并按指令编译进 wiki。
6. 混乱、多模态、会议类资料先写 `output/extract/...`：语音需文字摘要，图片需说明、时间、场景和关联项目，视频需关键片段和结论，外部资料需写「为什么收藏」和「对我有什么用」，再决定是否编译。
7. 输出文章、PPT、项目规划、汇报或方案时，优先读取 `wiki/自我模型.md`、`wiki/我的表达风格.md`，再检索相关知识点、人物/项目/方法论页，用已有判断和表达偏好组织内容。
8. 用户反馈“不像我”“判断不对”“表达不对”“太官方”“太空”“AI味太重”“观点过时”“方向不对”等时，判断是否属于稳定偏好或判断变化；稳定反馈应回写到自我模型、表达风格或相关页面。

## Wiki页面结构

每个 `知识点-*.md` 默认使用五段结构：

1. `摘要`
2. `实体`
3. `概念`
4. `对比`
5. `概述与综合`

普通知识点不强制写 `当前结论`、`观点演化`、`已废弃观点`、`可复用规则`。这些段落只在用户明确要求、库内已有对应段落，或作为人物、项目、方法论等对象页规则时使用。

### 文件命名（建议写入各库 AGENTS）

- 主题优先：`知识点-<主题>.md`；来源只写进 `实体`，不写进文件名。
- 主题名简洁可识别：中文主题片段默认 **4～12 字**；由长标题压缩时，在编译报告写「原标题 → 采用页名」。

## Q&A规则

每个知识库问题都必须保存到 `output/qa/<YYYY-MM-DD>/<slug>.md`。
如果答案形成了稳定知识点，可以归档到 `wiki/` 并记录日志。
```

## 对象型页面模板（人物 / 项目）

人物或项目对象页不使用知识点五段，也不使用 `知识点-<对象名>.md` 命名。人物页命名为 `人物-<人物名称>.md`；项目页放在对应项目文件夹内，命名为 `项目-<项目名称>.md`，作为该项目文件夹总说明。项目文件夹内其它专题仍使用 `知识点-<主题>.md`。

### 人物页面模板

```markdown
# 人物：<人物名>

## 基本信息

<只写事实：身份、领域、组织、公开背景、联系方式的脱敏索引等。不要写推测和判断。>

## 互动时间线

- <YYYY-MM-DD 或时间范围>：<发生过什么>（来源：[`源材料`](../../youdao/...)）

## 当前状态

<这个人现在在做什么；只写有来源或用户明确表达的信息，不确定就标注待确认。>

## 我的判断

- 更新时间：<YYYY-MM-DD>
- 判断：<只写用户本人明确表达的判断；没有就写“待用户判断”。不要由 LLM 替用户下结论。>

## 关系状态

- <合作 / 客户 / 朋友 / 潜在合作 / 需要谨慎 / 待确认>

## 注意事项

- <和这个人沟通要注意什么；区分事实依据和用户判断。>

## 相关项目

- [`项目页面`](../项目目录/项目-xxx.md)

## 相关原始资料

- [`源材料`](../../youdao/...)

## 已废弃观点

| 时间 | 旧观点 | 为什么废弃 | 替代观点 |
|------|--------|------------|----------|
| <YYYY-MM-DD> | <旧判断> | <废弃原因> | <当前替代判断> |
```

维护规则：事实写进「基本信息 / 互动时间线 / 当前状态」；判断只写进「我的判断」且标注更新时间。旧判断被新判断取代时，移入「已废弃观点」，不要和当前判断平级。

## 书本镜像输出模板（写入 `output/book-mirror/<YYYY-MM-DD>/<slug>.md`）

```markdown
# <书名或理论名> × 我的经验镜像

## 元信息

<只提炼原则、流程、判断框架和适用边界，不镜像全文>

## 对应关系

| 书中原则 / 流程 | 我的事迹 / 想法 / 做法 | 对我的方法论启发 | 置信度 / 空白 |
|---|---|---|---|
|  |  |  |  |

- <结论 1>
- <结论 2>
- <需要用户确认的判断必须标注，不得直接当作最终方法论>

## 需要我手动评估或补充的部分
```
