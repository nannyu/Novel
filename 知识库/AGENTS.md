# AGENTS — 个人知识库（duwu）

## Wiki 定位

wiki 是本知识库的核心阅读层和第二大脑工作层，不只是源材料索引。

用户应当通过阅读 wiki 页面，基本理解某个主题、人物、项目或方法论的当前状态、历史演化、关键判断和可复用经验。

`youdao/` 是底层证据层，主要用于核查细节、追溯来源和重新分析；日常查询、输出文章、方案、项目规划时优先基于 `wiki/`。

供 Agent 快速对齐：本仓把 `youdao/` 源材料整理成可导航的 `wiki/`。`wiki/` 是摘要型第二叙述，不是全文镜像；细节以源文件为准。具体执行流程、模板和输出路径由 `llm-wiki-kb` skill 负责，本文件只保留本库契约。

## 目录

| 路径               | 用途                            |
| ---------------- | ----------------------------- |
| `youdao/`        | 源材料，只读；不要无差别搬进 wiki。          |
| `wiki/`          | Agent 维护的编译层；优先可导航、可追溯、可增量更新。 |
| `wiki/自我模型.md`   | 用户当前身份、长期方向、做事原则、稳定偏好和当前判断。   |
| `wiki/我的表达风格.md` | 用户输出文章、方案、汇报、PPT时的表达偏好和禁忌。    |
| `output/`        | 中间产物与报告，如抽取、总结、书本镜像、Q&A、编译报告。 |

维护 `youdao/Cursor教程/` 时，先读 `youdao/Cursor教程/AGENTS.md` 与 `wiki/Cursor教程/教程更新与wiki同步规范.md`；该教程正文不默认硬套知识点五段。

## 基本原则

1. 编译范围以用户当次指定路径为准；信息不够就少而准地追问。
2. 改 `wiki/` 必须更新相关 `INDEX.md` 和 `_维护日志.md`。
3. 源材料只索引、摘要、链接；隐私和密钥等敏感字段只索引不抄录。
4. 知识点之间使用相对链接；`实体` 或来源段落里标明对应 `youdao` 路径。
5. 能增量修订就不要重复建页；结构变更记维护日志。

## 任务清单

任务清单由独立 `wiki-task-list` skill 处理。只有当用户要求“更新任务”“扫描任务”“整理任务清单”“列出最新任务”等任务清单操作时才调用。

目录：
- `wiki/任务清单/待办.md`
- `wiki/任务清单/已办.md`

规则：
- 只记录可执行、可复核事项。
- 已完成、已归档或不处理事项移入 `已办.md`，后续扫描必须排除。
- 涉及隐私、密钥、手机号等敏感内容，只保留来源路径和脱敏概述。

## 编译方式

### 普通知识点

`知识点-*.md` 默认使用五段结构：`摘要` → `实体` → `概念` → `对比` → `概述与综合`。

文件名主题优先，避免 `知识点-从某某文件提炼的某某主题.md` 这类来源命名。多源材料写进页内来源列表，不写进文件名。新增资料进入已有知识点时，优先保留演进脉络，而不是直接覆盖成一个最新总结。

### 对象型页面

人物、项目不硬套知识点五段，也不命名为 `知识点-<对象名>.md`。人物页命名为 `人物-<人物名称>.md`；项目页放在对应项目文件夹内，命名为 `项目-<项目名称>.md`，作为该项目文件夹总说明。项目文件夹内其它专题仍用 `知识点-<主题>.md`。

`我的判断` 只能来自用户本人手动输入或明确表达，LLM 只能整理、追问和标注依据，不能替用户下最终判断。历史页面中若已存在 `我的评估`，可视为 `我的判断` 的旧命名；后续新建和修订页面统一使用 `我的判断`。人物、项目、会议、聊天、资料中出现的相关实体，要按需回写到对应对象页。

人物页固定结构：

1. 基本信息
2. 互动时间线
3. 当前状态
4. 我的判断
5. 关系状态
6. 注意事项
7. 相关项目
8. 相关原始资料
9. 已废弃观点

项目页固定结构：

1. 当前结论
2. 基本信息
3. 时间线
4. 关键问题
5. 相关人物
6. 相关原始资料
7. 已废弃观点

项目页的 `当前结论` 必须放在页面顶部，包含：
- 是否值得继续
- 当前阶段
- 最大问题
- 下一步
- 我现在的态度
- 更新时间

### 原始资料抽取

会议、语音、图片、截图、视频、聊天、零散日记等混乱资料，先做结构化抽取，再决定是否入库。抽取稿写入 `output/extract/...`，用于后续总结、书本镜像或 wiki 编译；抽取稿不是最终 wiki 结论。

### 书本镜像

当用户指定书、文章、课程或理论，并要求与自己的经历、想法、做法、项目记录建立对应关系时，执行书本镜像。先写 `output/book-mirror/...`，再把稳定方法论、流程或对象页更新编译进 `wiki/`。没有真实对应时写空白，不强行牵连。

## 问答与输出

用户提问时先搜/读 `wiki/`，不足再查 `youdao/`，回答要引用路径，并保存到 `output/qa/...`。

当输出需要体现用户个人判断或表达风格时，必须优先读取：

1. `wiki/自我模型.md`
2. `wiki/我的表达风格.md`
3. 相关 `知识点-*.md`
4. 相关人物 / 项目 / 方法论页面

当用户要求输出文章、PPT、项目规划、汇报、方案或其它需要体现“我的判断方式”的内容时，不只检索事实型知识点；还要查相关方法论页、书本镜像、人物/项目页中的 `我的判断`，用已沉淀的流程和判断标准组织输出。

## 使用反馈回写

当基于知识库输出内容后，用户指出“不像我”“判断不对”“表达不对”“太官方”“太空”“AI味太重”“观点过时”“方向不对”等反馈时，Agent 应判断这是否属于稳定偏好或判断变化。

若是稳定反馈，应回写到：

- `wiki/自我模型.md`
- `wiki/我的表达风格.md`
- 相关知识点页的 `摘要`、`概念`、`对比` 或 `概述与综合`
- 相关人物 / 项目页的 `我的判断` 或 `当前结论`

如果反馈是否稳定不确定，先在回复中标注“可作为知识库偏好回写”，并询问是否写入；不要擅自把一次性情绪或临时修改写入长期自我模型。

## 健康检查

定期或大改后检查：页间矛盾、过时结论、孤岛页、缺失概念、缺失互链、可补资料空白。发现问题先提议，用户确认后再改库。

健康检查还应检查：

1. 重要知识点是否缺少稳定摘要或概述
2. 是否存在旧判断与新判断混在一起、没有在相关对象页或方法论页中标明取代关系
3. 是否存在只有事实整理、没有综合判断的高频主题
4. 输出反馈是否已经回写
5. `自我模型.md` 和 `我的表达风格.md` 是否过时

## 用户发起任务时带上

路径（如 `youdao/...`）、目标 wiki 页或编译方式、是否有不宜入库的隐私。

策略变更时同步改本文。
